The question

Which resource made your server slow?

resmon only ever shows you now. When someone says the server was unplayable last night, or that it has felt worse since Tuesday, there is nothing to look at. You restart things until it stops.

Pulse records main-thread health continuously, so the question has an answer.

How it measures

By timing its own lateness

FiveM runs every resource's threads cooperatively on one main thread. Pulse sleeps for a known interval and reports how much longer it actually took. A thread that asks for 50ms and wakes at 900ms proves the main thread was blocked for 850ms — time no resource could use, and what your players feel as rubber-banding and frozen peds.

It will not claim per-resource CPU

No server native provides it. Any tool showing you a server-side CPU breakdown by resource is inferring it. Pulse measures total stall time exactly, and works out the cause by correlating stalls with restarts over time.

Stall timing is a lower bound

Accurate to one probe interval — 50ms by default. The reported figure is the floor, not the exact number.

Attribution

Player count is the trap

Comparing the hour before a restart with the hour after does not work. Your server is genuinely worse at 21:00 than at 09:00 because five times as many people are on it. Do it naively and every resource that restarts during the evening climb looks guilty. So Pulse never compares raw averages.

01

The baseline for the hours after a restart is the same clock hours on previous days. Population follows the clock, so like is compared with like.

02

Within that, samples are matched by player count — only overlapping population ranges are compared, each weighted by the smaller side's evidence.

03

A step at the change itself is also required. A regression you have not fixed poisons tomorrow's baseline, so every restart on the nights after would look guilty. This is what keeps your nightly restart cycle out of the results.

04

Confidence reflects evidence, not effect size — and the dashboard tells you which comparison it used, so you can disagree with it.

On three days of a simulated 200-resource server with a deliberately broken update, it names one resource, the right one, with zero false positives on the nightly restart cycle. Given one day of history it still finds it, and says the confidence is low instead of pretending otherwise.

Overhead

It does not cost you performance

A performance monitor that costs performance is worse than none — you cannot separate its overhead from the fault you installed it to find. So the collector measures its own CPU, ships that number in every payload, shows it on the dashboard, and halves its own sampling rate if it ever goes over budget.

The dashboard

Everything on one page

Health with the numbers behind it, the stall timeline with restart markers, what changed and how confident it is, recent restarts, and the collector's own cost. Discord alerts for sustained slowdowns, new regressions, and the collector going quiet — with cooldowns, so you are not pinged into muting the channel.

Install

Two pieces

The backend stores and analyses; the collector is a resource on your server. One container, SQLite, one file on disk — there is no database server to run. The install script prints a config block with your endpoint and token already in it.

# starts the backend, then prints what to paste into server.cfg
sh install.sh
# then, in the FiveM server console
pulse test

[pulse] PASS (HTTP 200, 41ms)
[pulse] OK. The backend accepted this server's token.

If that check fails, the last line names the thing to change. A rejected token, a wrong path, and a backend nothing can reach are three different messages, not one generic error. Every collector setting has a convar, so tuning survives an update.

Status

What is not proven yet

Everything above runs and is covered by 117 tests. But it has been validated against a FiveM simulator — a virtual-time server reproducing cooperative threading and main-thread stalls, which the collector runs inside completely unmodified — and not yet against a live server.

That is exactly why it is free and why the collector is MIT: seven files of dependency-free Lua you can read before putting anything on your server. Please read it. And if it blames the wrong resource, that is the most useful bug report you can send — it is real-world data the simulator cannot give.
